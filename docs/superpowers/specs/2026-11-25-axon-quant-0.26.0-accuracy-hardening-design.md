## 1. 背景与目标

基准分析确认的五处已实锤裂缝/缺口:

| # | 问题 | 触点 |
|---|------|------|
| A | 多品种同帧 HashMap 迭代序驱动 rebalance 执行序与 order id 分配,重复运行结果可能不同 | `axon-backtest/src/engine.rs:2519,2630,1449,2274`(`bt_state.legs`/`position_states`:engine.rs:485,:505)、`axon-backtest/src/margin.rs:258`;自述见 `axon-worker/src/shadow.rs:43-46` |
| B | OHLC 校验仅 `debug_assert!`,release 失效;`validate_ohlc()` 生产零调用 | `axon-core/src/market/bar.rs:97-104,110-130` |
| C | 聚合器去重分桶 16 根,迟到超窗重复 bar 静默二次放行 | `axon-kernel/src/aggregator.rs:19-27,38,199-203,238-250` |
| D | 任何撮合/聚合语义变更没有数值指纹护栏,回归靠等值测试的既有负载 | `axon-integration-tests`(无 canonical) |
| E | `todo!/unimplemented!`、裸 unwrap 无机器门禁;故障→测试→文档闭环无成文约定 | axon-llm 10 处 cfg(test) 桩;`docs/{zh,en}/about/contributing.md` |

**目标**:0.26.0 单版本内,以两波段(先纯护栏、后行为修复)消除 A/B/C,并建立 D/E 的机器与流程护栏。全部改动落在 Phase 0 验收标准内,不越界到 P1(D1–D5)。

**不做(YAGNI)**:确定性仿真框架/种子扫描、Latency/Fill 模型、NAV 漂移标定、审计链内化、duplicate 事件化、`--skip-invalid` 报告模式(数据质量管道属 D1)、兼容层。legacy 三路径退役属 A3,不在本版本。

## 2. 波段划分与提交序

```
波段一(纯护栏,零行为变更)
  C1 = O5 lint 骨架
  C2 = O6 闭环约定文档
  C3 = O4a golden 基础设施(单品种负载,天然确定性,不依赖 O1)
波段二(行为修复,每笔被波段一护栏接住)
  C4 = O1 迭代序修复 + 同负载双跑 proptest(红→绿同 commit)
  C5 = O3 水位线剪枝 + 告警计数(事件流形态不变)
  C6 = O2 校验门(历史拒绝/实时降级)
  C7 = O4b 多品种负载锁存 O1 新语义 + CHANGELOG + 全量 verify
```

护栏时序依据:C3 单品种负载与 O1(多品种执行序)零交集,可以先上指纹;C4 修完后 C7 以多品种负载把"字典序决策"锁存为新基线——指纹永远建在稳定语义上。

**版本/分支前置**(按 AGENTS.md 铁律):切分支 `0.26.0` → `Cargo.toml` + `pyproject.toml` 版本号两处 → `cargo generate-lockfile` → 本地 `clippy/test/build --locked` 全绿后才允许提交。commit 英文 `feat:/fix:/test:/chore:/docs:` 前缀。

## 3. 各项技术设计

### 3.1 C1 — O5 lint 骨架

**现状**:根 `Cargo.toml` 无 `[workspace.lints]`,各 crate 无 `[lints]`;`clippy.toml` 不存在。

**设计**:
1. 根 `Cargo.toml` 新增:
   ```toml
   [workspace.lints.clippy]
   todo = "deny"
   unimplemented = "deny"
   print_stdout = "deny"
   ```
   只放**已验证零违规**的常用项;裸 `todo!`/`unimplemented!` 恰好 10 处且全部在 axon-llm 的 `#[cfg(test)]` 桩(`declarative_agent.rs:314,321`、`trading/exchange.rs:854-993` 8 处)——两处模块级 `#![cfg_attr(test, allow(clippy::todo, clippy::unimplemented))]` 精确豁免。
2. 32 个 crate 的 Cargo.toml 逐个加 `[lints] workspace = true`。全量引入而非灰度——首批 lint 已验证全局零违规;风险被 `--all-targets` CI 兜底。
3. `clippy.toml` 新建(空骨架 + 注释,为后续 `cognitive-complexity-threshold` 等预留)。
4. kernel 单刀灰度 unwrap:`axon-kernel/src/lib.rs` 追加 `#![deny(clippy::unwrap_used)]`(生产代码仅 3 处 `.expect`/`max()`,不受 unwrap_used 影响)。backtest/core 的 unwrap 灰度**不在本版本**。
5. `docs/zh/about/contributing.md`「开发约定」补一行 lint 约定(与 C2 同文件,合并提交)。

**验收**:`cargo clippy --workspace --all-targets --locked -- -D warnings` 与 `--features python` 全绿;向 axon-kernel 生产代码加入裸 `unwrap()` CI 即红。

### 3.2 C2 — O6 故障闭环约定

**设计**:contributing 中英双语同步新增小节「回归与修复约定 / Regression & Fix Conventions」(zh 放「开发约定」下,en 放 `## Code Style` 后)。三条约定:
1. 行为修复在 CHANGELOG 的 Fixes 中**引用 issue/报告者**;
2. 回归修复对应的测试注释以 `Regression:` 开头,正文含复现条件与修复 commit 引用点;
3. golden 指纹文件的 `reasoning` 字段必须说明"为何更新"(改了什么语义/对应 issue),无理由的指标变更=违规。

双语内容语义对齐(IT 的 docs-drift job 只查文件结构,但内容必须同步翻译避免漂移恶化)。CHANGELOG 格式本身已符合 Keep a Changelog,不改动模板。

**验收**:docs-drift job 绿;下一笔 fix 起按约定执行(本版本 CHANGELOG 节即示范)。

### 3.3 C3/C7 — O4 golden 指纹基础设施

**Spec 字段底稿**:复用 `kernel_loop.rs:1164-1271 assert_same_run` 的字段清单——标量(total_pnl/max_drawdown/final_nav/total_fees/total_funding_pnl/win_rate/sharpe_ratio/shortfall_count 等)、曲线(bar_nav_curve/bar_balance_curve/equity_curve 逐点,1e-9 相对容差)、结构全等(positions/leg_targets/marks/fills_detail/trades/liquidation_events)。

**设计**:
1. `RunResult`/`KernelResult` 补 `#[derive(Serialize)]`(engine.rs:224 起,纯 additive;内部 float 字段直接 serde 序列化,曲线逐点值含容差语义由测试侧处理——指纹 JSON 存"规范值",比对在测试代码里做浮点容差而非字符串全等)。
2. 新文件 `crates/axon-integration-tests/src/canonical.rs`:
   - `CanonicalWorkload` 枚举:`ReplayOnly / ScheduledMarketOrders / PassiveLimitOrders / EmaCross`(C3 四负载)+ `MultiSymbolRebalance`(C7 追加);
   - 负载构造:复用 `kernel_loop.rs tests` 的 `Kernel::new(KernelConfig, BacktestSink)` + 自写 `impl StrategyHost` 模板(fixture `frames_3bars`:858-866 与双品种 :988-1027 为蓝本);EMA 交叉在 Host `on_event(BarClosedEvent)` 内自算 EMA 后返 `OrderIntent::SetTarget`;
   - `run_fixture(workload) -> CanonicalReport { workload, config_hash, metrics, curves }`;
   - 对比逻辑:`load_reference_json(include_str!)` → 字段比对(标量/结构全等,浮点走容差)→ 失败时输出 diff 并提示更新流程;
3. 指纹 JSON:`crates/axon-integration-tests/tests/fixtures/canonical/{replay_only,scheduled_market_orders,passive_limit_orders,ema_cross,multi_symbol_rebalance}.json`,schema:
   ```json
   { "reasoning": "...为何更新...", "workload": "...", "kernel_config": {...}, "metrics": {...}, "curves": {"bar_nav": [...], "equity": [...]} }
   ```
4. **C3 只含单品种四负载**;C7 追加 `MultiSymbolRebalance`( legs ≥2、同帧 rebalance 触发 `engine.rs:2519` 路径)锁存字典序语义;两批各自独立 JSON 文件,互不触碰。
5. 更新流程:语义有意变更 → 改代码 + 以新输出重生成 JSON + 填 `reasoning` + CHANGELOG 说明;无 reasoning 的指纹变更按 C2 约定视为违规。

**验收(C3)**:`cargo test -p axon-integration-tests canonical` 绿;人为篡改任一 metric(测试内临时改 Host 比例)即红。
**验收(C7)**:多品种负载指纹绿;C4 之前该负载**不允许入库**(防止锁存非确定语义)。

### 3.4 C4 — O1 迭代序修复

**裂缝机制**:`bt_state.legs: HashMap<Instrument, LegConfig>`(engine.rs:505)与 `position_states: HashMap`(engine.rs:485)在当帧 collect 后按 HashMap 随机序消费:`:2519-2528` rebalance 下单循环 + `:2630-2632` `rebalance_next_id.fetch_add`(id↔品种漂移本体)、`:1449-1472` EOD 强平(`EOD_LIQUIDATE_ID_BASE + idx`)、`:2274-2300` 逐仓划转(顺序影响现金不足时的"夹小"分配)、`margin.rs:258` 逐仓强平 plan(全仓段 `:287-288` 已修,带注释,是范式)。

**设计**:sort-on-collect——四处收集循环在 `collect()` 后追加 `.sort_by(|a, b| a.0.cmp(b.0))`(Instrument 键序即字典序;不换容器类型,最小 diff)。
- `engine.rs:2519`(legs→rebalance 执行序)
- `engine.rs:1449`(position_states→EOD 强平)
- `engine.rs:2274`(position_states→逐仓划转)
- `margin.rs:258`(specs→逐仓强平 plan,对齐 :288 已修段)

**确认非裂缝(勿改)**:`axon-kernel/src/core.rs:167-169`(BTreeMap)、`pump.rs:26` 帧内 Vec(BTreeMap 展平,:71,:84)、`lifecycle.rs:96/125/155` Vec 消费、`kernel_loop.rs` frame_states(BTreeMap)、`sink.rs:295`/`host.rs:61-65` 查表 HashMap、`aggregator.rs:46/48` keyed、`axon-ensemble/src/voting.rs:28-41`(全序排序后无关)。事件队列同刻并列序=入队序(`event_queue.rs:74-87`,seq 单调),本轮不动。

**测试设计**(同 commit 红→绿):
1. `kernel_loop.rs tests` 新 proptest 块:同负载双跑(两次 `Kernel::new` + 同参数)→ `assert_same_run` 逐字段全等(std RandomState 每实例随机,无需手动 seed 也能捕捉裂缝,修复后恒等)。挂 `proptest-regressions/` 语料。
2. 修复完成后追加「symbol 改名置换等值」测试:相同语义负载对调品种名(BTC↔ETH),断言"除名称外的运行结果"等值——检测决策序与品种名解耦(排序后天然成立)。
3. CHANGELOG 声明:**"多品种帧的 order id 分配与成交执行序变为确定性字典序(修复 HashMap 迭代序非确定性);多品种回测的逐仓划转/强平结果数值可能变化"**。

**验收**:proptest(含 regression 文件)绿;C7 多品种负载指纹绿;`verify` 全绿。

### 3.5 C5 — O3 水位线 + 告警计数

**现状**:`mark_seen`(:238-250)contains→push_back→超 16 pop_front;迟到 >16 周期的重复 bar `is_duplicate=false` → `observe_kline` :183-195 **静默二次放行**(tick 路径 :101/:115 同理);交易所 Kline 无 seq 字段(`axon-exchange/src/types.rs:166-176`),seq 去重不可行。

**设计**(放行形态不变):
1. 桶结构 `VecDeque<i64>` 保留,`SEEN_PER_KEY` 语义降级为"上限兜底";
2. 新增水位线推进:每 key 记录连续推进的最高收市时刻 `barrier`;`mark_seen` 时剪枝 `< barrier - WATERMARK_LAG`(新常量,默认 64 根周期)的历史戳——内存上界从"16 根的 Vec 生长"变为稳态常数;
3. **漏判可见化**:`is_duplicate=false` 且 `bar.timestamp < barrier` 时(即"越过水位线的迟到重复")→ `tracing::warn!`(instrument+interval+ts)+ `duplicates_missed += 1` 计数,**该 bar 仍照现有路径放行**(第二次进内核的行为与今日一致,事件流零变化、指纹零扰动);
4. 窗口内重复拦截行为不变(:199-203)。

**验收**:单测——构造迟到 17 周期重复 bar:断言 warn 产生、`duplicates_missed` 计数 ≥1、事件流与基线(用 C3 单品种负载双跑比)逐字段等值;内存剪枝生效(stamp 桶长度不随回放长度增长)。

### 3.6 C6 — O2 数据校验门

**装药点(仅两处)**:
1. **历史**:`axon-kernel/src/pump.rs build_frames`(:54 前后,已是 `Result<Vec<GridFrame>, KernelError::Pump>` 链)逐根 `bar.validate_ohlc()` → Err(`KernelError::Pump` 携带 symbol+bar ts+违规字段),**严格拒绝**:整帧失败、回测不启动(fail-fast,拒绝脏数据直达撮合)。
2. **实时**:`axon-worker/src/pump.rs on_kline`(:272,Bar 构造 :286-293 之后)同 gate;失败 → 丢弃该 bar + `tracing::warn!` + 计数(**不打挂主回路**,对照现成"解析失败丢弃+warn":279-284 模式)。

**设计内豁免**:旧 `crates/axon-worker/src/backtest.rs::BacktestRunner` 历史网格路径不经过上述两个装药点(直接读网格、不经 kernel 的 `build_frames`),**不施 OHLC 门**——这是明确的设计边界,不是漏装;门只在「kernel 历史入库」与「worker 实时 pump」两处生效。

**QualityReport**(新结构,`axon-kernel`):
```rust
#[derive(Debug, Clone, Default, Serialize)]
pub struct QualityReport {
    pub ohlc_rejected: u64,        // 拒收的 OHLC 非法 bar
    pub invalid_qty_dropped: u64,  // 负量/零量丢弃(aggregator 现有行为的计数化)
    pub duplicates_missed: u64,    // C5 的漏判告警计数
}
```
- `#[serde(default)]` 兼容旧 journal;**不进 RunManifest**:`ensure_manifest_match`(:360)是全结构 `!=`,统计字段会造成"同配置跑两次指纹不同"。QualityReport 在 run 结束随 KernelResult 输出、写 `*.quality.json` 侧车文件(与 `*.reconcile_last_ok.json` 同目录惯例)。
- `invalid_qty_dropped` 把 aggregator 现有 `.max(0.0)`(:89-90/:261)静默行为计数化,不加新拦截。

**测试设计**:脏数据 fixture 矩阵按 `validate_ohlc` 现有规则枚举五类 OHLC 违例(high<low、open>high、open<low、close>high、close<low),另含乱序 ts、重复 ts、缺口;参数化;**debug 与 release 双跑**(`cargo test --release -p axon-kernel`)证明 `debug_assert!` 时代的行为差异已消除。

**验收**:脏 fixture 矩阵 debug+release 全绿(历史据拒/实时降级各断言);干净数据集的 C3 指纹不变(零扰动)。

## 5. 风险与兼容声明

| 风险 | 缓解 |
|---|---|
| C4 改变多品种回测数值(划转夹小/强平顺序敏感) | CHANGELOG 显式声明 + C7 指纹锁存新语义 |
| C6 历史严格拒绝:现存脏历史数据令旧回测失败 | 错误信息带 symbol+ts+字段定位;报告模式属 D1,记录不做 |
| C1 全量 [lints] 引入暴露未知违规 | 首批 lint 已验证全局零违规;`--all-targets --locked` CI 兜底;发现即修或临时 crate 级 allow+issue |
| C5/C6 若发生事件流/指纹扰动 | 属设计违规:按 C2 约定,"事件流零变化"是这两项的硬验收 |
| 逐仓划转排序改变实得保证金金额 | 同 C4 第一条,属"业化非确定账务为确定账务"的目的本身 |
