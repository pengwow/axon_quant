# axon_quant 0.14.0 立项：LLM 异步流式 Python 绑定

> **Goal:** 为 `axon-llm` 的 PyO3 绑定补齐异步能力：`chat` / `chat_with_tools` 的 async 版本 + `stream_chat` 的真异步流式（`async for` 逐 chunk），消除上层（QuantCell 等 FastAPI 产品）被迫 `block_on` / `to_thread` / 丢失流式实时性的两大缺口。

---

## 1. 背景

0.13.0 已暴露 `chat` / `chat_with_tools` / `stream_chat`，但全部是**同步阻塞**绑定（内部 `runtime.block_on`）：

| 缺口 | 现状 | 对上层的影响 |
|------|------|-------------|
| 同步阻塞 | `block_on` 独占线程直到完成 | FastAPI async 端点只能 `asyncio.to_thread` 绕行，线程切换开销 + 并发受限 |
| 伪流式 | `stream_chat` 一次性收集全部 `TokenDelta` 返回 `list[dict]` | 上层无法"边生成边推送"，前端实时体验丢失 |

架构定位结论（见 QuantCell 侧 `2026-09-01-llm-layer-deep-integration-design.md`）：**交互式产品层（会话/记忆/流式 UI）归 QuantCell，引擎层（高性能 LLM 调用/推理/决策）归 axon_quant**。异步流式绑定属于引擎层职责，是打通两层契约的关键缺口，故立项。

## 2. 目标 / 非目标

### 目标

1. `chat_async(messages)` / `chat_with_tools_async(messages, tools)`：async 方法，返回与同步版相同结构的 dict，**不阻塞** Python 事件循环。
2. `stream_chat_async(messages)`：返回异步迭代器，支持

   ```python
   async for chunk in backend.stream_chat_async(msgs):
       # chunk: {"type": "content"|"reasoning"|"tool_call_start"|"tool_call_delta"|"done", ...}
   ```

   逐 chunk 实时产出，语义与同步版 `stream_chat` 的 dict 元素完全一致。
3. 保留全部现有同步方法（向后兼容，0.13.0 调用方零改动）。
4. Python 包装层 `python/axon_quant/llm.py` 补充 async 用法文档与示例。

### 非目标

- 不做会话管理 / 记忆整合 / 多厂商模型配置（产品层职责，归 QuantCell）。
- 不做 `models.list()`（非 chat completion 能力）。
- 不改 Rust 侧 `LLMBackend` trait 与 SSE 解析逻辑（纯绑定层增强）。

## 3. API 设计

### 3.1 Rust 绑定（`crates/axon-llm/src/python/backend.rs`）

```rust
#[pymethods]
impl PyLLMBackend {
    // 新增:异步 chat(不阻塞事件循环)
    fn chat_async<'py>(&self, py: Python<'py>, messages: Vec<Bound<'py, PyAny>>)
        -> PyResult<Bound<'py, PyAny>>;              // 返回 awaitable

    // 新增:异步 chat_with_tools
    fn chat_with_tools_async<'py>(&self, py: Python<'py>,
        messages: Vec<Bound<'py, PyAny>>, tools: Vec<Bound<'py, PyAny>>)
        -> PyResult<Bound<'py, PyAny>>;              // 返回 awaitable

    // 新增:真异步流式,返回 PyLLMStream(实现 __aiter__/__anext__)
    fn stream_chat_async<'py>(&self, py: Python<'py>, messages: Vec<Bound<'py, PyAny>>)
        -> PyResult<PyLLMStream>;
}

/// 异步流迭代器:`async for chunk in ...` 逐 TokenDelta 产出 dict
#[pyclass]
struct PyLLMStream { /* runtime + 共享流状态 */ }

#[pymethods]
impl PyLLMStream {
    fn __aiter__(slf: PyRef<'_, Self>) -> PyRef<'_, Self>;
    fn __anext__<'py>(&self, py: Python<'py>) -> PyResult<Bound<'py, PyAny>>; // awaitable
}
```

### 3.2 Python 用法

```python
from axon_quant.llm import make_backend

backend = make_backend({"backends": [{"base_url": ..., "api_key": ..., "model": ...}]})

# 非阻塞调用(可在 FastAPI async 端点直接 await)
resp = await backend.chat_async([{"role": "user", "content": "hi"}])

# 真流式:边生成边推送
async for chunk in backend.stream_chat_async(msgs):
    if chunk["type"] == "content":
        await push_to_websocket(chunk["content"])
    elif chunk["type"] == "reasoning":
        ...  # DeepSeek-R1 思考链
```

## 4. 实现要点

### 4.1 新增依赖

`pyo3-async-runtimes = { version = "0.28", features = ["tokio"], optional = true }`，挂到 `python` feature。用于把 tokio future 桥成 Python awaitable（`future_into_py`）。这是 PyO3 官方异步桥接方案。

### 4.2 关键机制

1. **awaitable 构造**：`chat_async` 内用 `pyo3_async_runtimes::tokio::future_into_py(py, fut)`，`fut` 在 `PyLLMBackend` 自有 tokio runtime 上执行 `backend.lock().await.complete(&msgs)`，完成后 GIL 内转 dict。
2. **流状态持有**：`stream_complete` 返回 `impl Stream + 'static`，但需持有 `MutexGuard` 跨 await。用 `Arc::clone(&inner)` + `lock_owned().await` 拿 `OwnedMutexGuard`，连同 `Box::pin(stream)` 存进 `PyLLMStream` 的共享状态（`Arc<tokio::sync::Mutex<StreamState>>`），使迭代器可 `'static` 存储。
3. **`__anext__` 语义**：每次调用返回一个 awaitable，await 时取流中下一个 `TokenDelta` 转 dict；流结束返回 `Err(StopAsyncIteration)`，Python `async for` 自动正常终止。
4. **错误传递**：流中 `LLMError` 映射为 `PyRuntimeError` 抛出（与同步版 `map_err` 一致）。
5. **复用**：`delta_to_pydict` / `parse_py_message` / `parse_py_tool_definition` 全部复用，不重复实现。

### 4.3 并发注意

`PyLLMBackend.inner` 是 `Arc<tokio::sync::Mutex<OpenAICompatBackend>>`：同一 backend 实例上并发的多个 `stream_chat_async` 会串行（锁跨整个流生命周期）。文档中注明：**并发流请创建多个 backend 实例**（`make_backend` 开销小，每实例独立 runtime）。是否改为无锁多路复用留待后续版本评估，不在本期。

## 5. 兼容性

- 同步 `chat` / `chat_with_tools` / `stream_chat` 原样保留，行为不变。
- `LLMBackend` trait、SSE 解析、`TokenDelta` 均不动。
- wheel 结构不变（`axon_quant._native` + `axon_quant.llm` 包装层）。

## 7. 版本与发布流程

1. 新建分支 `0.14.0`（从 `0.13.0`）。
2. 版本号同步：`Cargo.toml` workspace / `pyproject.toml` / `CHANGELOG.md`。
3. 本地 `make verify` 通过 → 提交 → 推送 `origin/0.14.0`。
4. 用户手动构建 wheel 并发布 PyPI（`axon-quant==0.14.0`）。
5. QuantCell 升级：`cd backend && uv lock --upgrade-package axon-quant && uv sync`，验证 `LLMBackend` 含 `chat_async` / `stream_chat_async`。

## 8. 验收标准

1. `await backend.chat_async(...)` 在 asyncio 事件循环中不阻塞其他协程（可用并发 sleep 协程验证）。
2. `async for chunk in backend.stream_chat_async(...)` 逐 chunk 产出，`content` / `reasoning` / `tool_call_*` / `done` 类型与顺序与同步版一致。
3. 流结束正常退出循环（StopAsyncIteration），流中错误抛 `RuntimeError`。
4. 同步三方法行为零变化（现有测试全过）。
5. `make verify` 全绿；`0.13.0` 分支不受影响。
