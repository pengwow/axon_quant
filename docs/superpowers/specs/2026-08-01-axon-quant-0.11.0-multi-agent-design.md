# axon_quant 0.11.0 — Multi-Agent 投票共识 + LLM 基础设施收尾

**日期**：2026-08-01
**版本**：0.11.0
**前置版本**：0.10.1（LLM 智能体交易：ReAct + provider 抽象 + tool calling + trajectory 落盘）
**实施路径**：底层优先（基础设施 → Multi-Agent → 用户工具）

---

## 1. 目标与范围

0.11.0 是 0.10.0 LLM 主线的自然收尾，完成原 spec 中明确推迟的 E7-E12 全部 6 项：

| 编号 | 内容 | 决策 |
|------|------|------|
| E7 | Multi-agent | 投票共识：多 trader 独立决策 → ensemble 聚合 → risk 一票否决 |
| E8 | Web UI → CLI 增强 | 砍掉 Web UI，做 rich CLI 可视化 + trajectory 离线回放分析 |
| E9 | Multi-LLM ensemble | 集成到 E7 投票流程中（复用 `axon-ensemble` voting） |
| E10 | 远程 provider | 一个通用 OpenAI-compatible HTTP provider |
| E11 | Trajectory → SFT | 质量过滤 + 数据格式化 + HuggingFace TRL 训练脚本骨架 |
| E12 | Token/cost 控制 | 轻量级：计数器 + 汇总报告 + 超预算 warning（不中断） |

**不在范围**：
- 实盘对接（留 0.12.0）
- Web UI / Gradio / Streamlit
- Anthropic 原生 SDK provider（OpenAI-compat 已覆盖）
- Trajectory → RL reward shaping（留后续）

## 3. E10：OpenAI-Compatible Provider

**位置**：`crates/axon-llm/src/backends/openai_compat.rs`

```rust
pub struct OpenAICompatProvider {
    base_url: String,       // e.g. "https://api.openai.com/v1"
    api_key: String,        // 从环境变量或配置注入
    model: String,          // e.g. "gpt-4o", "qwen-plus"
    max_tokens: u32,        // 单次响应上限，默认 2048
    temperature: f32,       // 默认 0.7
    timeout: Duration,      // 请求超时，默认 30s
    client: reqwest::Client,
}
```

### 设计要点

- 实现已有 `LLMProvider` trait（`chat(&self, messages: &[Message]) -> Result<Response>`）
- 请求/响应格式完全走 OpenAI `/chat/completions` 协议（Azure、国内端点均兼容）
- 配置通过 `OpenAICompatConfig` builder：`base_url` / `api_key` / `model` 三个必填，其余有默认值
- 错误处理：HTTP 4xx/5xx → `LLMError::ProviderError`，超时 → `LLMError::Timeout`
- 自动重试 1 次（仅 5xx / 超时），4xx 不重试
- 新增依赖：`reqwest`（workspace 级引入，features = ["json"]）
- Python 端：`make_openai_compat_provider(base_url, api_key, model)` pyfunction

### 环境变量支持

```bash
OPENAI_API_KEY=sk-xxx
OPENAI_BASE_URL=https://api.openai.com/v1  # 可选覆盖
```

Config builder 优先使用显式传入值，fallback 到环境变量。

## 4. E12：TokenMeter

**位置**：`crates/axon-llm/src/meter.rs`

```rust
pub struct TokenMeter {
    inner: Box<dyn LLMProvider>,   // 装饰器模式
    input_tokens: AtomicU64,
    output_tokens: AtomicU64,
    call_count: AtomicU64,
    budget: Option<TokenBudget>,   // 可选预算配置
}

pub struct TokenBudget {
    pub max_input_tokens: u64,
    pub max_output_tokens: u64,
    pub warn_threshold: f32,       // 0.8 = 80% 时 warning
}

pub struct TokenReport {
    pub input_tokens: u64,
    pub output_tokens: u64,
    pub total_tokens: u64,
    pub call_count: u64,
    pub estimated_cost_usd: f64,   // 按 model 定价估算
    pub over_budget: bool,
}
```

### 设计要点

- 装饰器包裹任意 `LLMProvider`，对上层 agent 完全透明
- token 计数来源：
  - OpenAI-compat：从响应 `usage.prompt_tokens` / `usage.completion_tokens` 读取
  - Mock / Ollama：`chars / 4` 启发式估算
- 超预算行为：`warn_threshold` 触发 `tracing::warn!`，**不中断执行**
- `report()` 方法随时可取当前汇总；run 结束后由 orchestrator 打印
- cost 估算：内置 model → (input_price_per_1k, output_price_per_1k) 小表，未知 model 默认 $0
- PyO3：`PyTokenMeter` 暴露 `report()` → Python dict

### 组合使用

```rust
let provider = OpenAICompatProvider::new(config);
let metered = TokenMeter::new(Box::new(provider), Some(budget));
let agent = ReActAgent::new(Arc::new(metered), tools);
// agent 无感知 meter 存在
```

## 5. E7 + E9：Multi-Agent 投票共识层

**位置**：`crates/axon-llm/src/swarm/`（复用已有骨架）

### 5.1 角色定义

| 角色 | 数量 | 职责 |
|------|------|------|
| Trader Agent | N（默认 3） | 各自独立跑 ReAct loop，输出 `Action` + confidence |
| Risk Agent | 1 | 审核聚合结果，可一票否决（返回 Hold） |
| Orchestrator | 1 | 编排流程：分发 bar → 收集投票 → 聚合 → risk 审核 → 输出 |

### 5.2 决策流程

```
Bar 到达
    │
    ├──→ Trader A (ReAct) ──→ Action{Buy, 0.8}
    ├──→ Trader B (ReAct) ──→ Action{Buy, 0.6}
    └──→ Trader C (ReAct) ──→ Action{Hold, 0.0}
                │
                ▼
    ┌─────────────────────────┐
    │  Ensemble Voting        │  ← axon-ensemble::voting
    │  weighted majority:     │
    │  Buy = 0.8+0.6 = 1.4   │
    │  Hold = 0.0            │
    │  → 聚合结果: Buy(0.7)  │
    └────────────┬────────────┘
                 ▼
    ┌─────────────────────────┐
    │  Risk Agent             │
    │  检查:                   │
    │  - 当前持仓/敞口         │
    │  - 连续亏损次数          │
    │  - 单 bar 最大仓位       │
    │  → approve / veto       │
    └────────────┬────────────┘
                 ▼
         Final Action (Buy 0.7) 或 Hold (被否决)
```

### 5.3 核心结构

```rust
// orchestrator.rs
pub struct SwarmOrchestrator {
    traders: Vec<ReActAgent>,           // N 个独立 trader
    risk_agent: RiskAgent,              // 1 个 risk 审核
    voting: Box<dyn VotingStrategy>,    // 复用 axon-ensemble
    token_meter: Arc<TokenMeter>,       // 共享计量
    trajectory: TrajectoryRecorder,     // 记录完整投票过程
}

impl SwarmOrchestrator {
    pub fn on_bar(&mut self, bar: &Bar) -> SwarmDecision { ... }
}

pub struct SwarmDecision {
    pub final_action: Action,
    pub votes: Vec<AgentVote>,          // 每个 trader 的原始投票
    pub aggregated: AggregatedVote,     // 聚合结果
    pub risk_verdict: RiskVerdict,      // Approve / Veto(reason)
    pub token_usage: TokenReport,       // 本 bar 的 token 消耗
}
```

### 5.4 投票策略（复用 `axon-ensemble`）

```rust
pub trait VotingStrategy: Send + Sync {
    fn aggregate(&self, votes: &[AgentVote]) -> AggregatedVote;
}

// 0.11.0 内置两种：
// 1. WeightedMajorityVote — confidence 加权，超阈值(默认 0.5)胜出
// 2. UnanimousVote — 全票一致才通过（保守模式）
```

### 5.5 Risk Agent 否决逻辑

```rust
pub struct RiskAgent {
    max_position: f64,          // 单方向最大仓位
    max_consecutive_loss: u32,  // 连续亏损 N 次后否决开仓
    max_drawdown: f64,          // 回撤超阈值否决
}

impl RiskAgent {
    pub fn review(&self, action: &AggregatedVote, ctx: &RiskContext) -> RiskVerdict;
}
```

- Risk Agent **不走 LLM**，纯规则引擎（快、确定、可审计）
- 否决时记录 reason 到 trajectory

### 5.6 Trajectory Schema v0.11.0

在 0.10.0 schema 基础上扩展：
- 新增 `votes` 数组：每个 trader 的 action + confidence + reasoning
- 新增 `aggregation` 字段：投票策略名 + 聚合结果
- 新增 `risk_verdict` 字段：approve/veto + reason
- 新增 `token_usage` 字段：per-bar 累计 input/output tokens

### 5.7 PyO3 暴露

```python
from axon_quant._native import PySwarmOrchestrator

orch = PySwarmOrchestrator(
    providers=[provider_a, provider_b, provider_c],
    risk_config={"max_position": 0.5, "max_consecutive_loss": 3},
    voting="weighted_majority",
)
decision = orch.on_bar(bar_dict)
# decision: {"final_action": ..., "votes": [...], "risk_verdict": ..., "token_usage": ...}
```

## 7. E11：Trajectory → SFT 训练管线

**位置**：`python/axon_quant/training/sft/`

```
python/axon_quant/training/sft/
├── __init__.py
├── filter.py        # 质量过滤
├── format.py        # SFT 数据格式化
└── train.py         # TRL 训练脚本骨架
```

### 7.1 质量过滤（`filter.py`）

过滤规则：
1. 只保留最终 PnL > 0 的 run（正样本）
2. 去除 confidence < 0.3 的决策（低质量）
3. 去除被 risk veto 的 bar（噪声）
4. 可选：只保留 top-K sharpe 的 run

### 7.2 SFT 数据格式化（`format.py`）

输出 chat 格式 JSONL（兼容 TRL `SFTTrainer`）：

```json
{
  "messages": [
    {"role": "system", "content": "You are a trading agent. Given market data, output action."},
    {"role": "user", "content": "Bar: O=67230 H=67450 L=67100 C=67380 V=1234\nPosition: 0.0\nPnL: 150.2"},
    {"role": "assistant", "content": "{\"action\": \"Buy\", \"confidence\": 0.82, \"reasoning\": \"SMA crossover confirmed by volume spike\"}"}
  ]
}
```

- 输出格式：JSONL，兼容 `datasets.load_dataset("json")`
- Multi-agent 模式：每个 trader 的决策独立成一条训练样本

### 7.3 训练脚本骨架（`train.py`）

```bash
python -m axon_quant.training.sft.train \
  --data artifacts/sft_data.jsonl \
  --model Qwen/Qwen2.5-7B-Instruct \
  --output_dir ./sft_output \
  --epochs 3
```

- 核心逻辑 ~80 行，参数全部 CLI 可配
- 不锁定具体模型，`--model` 传 HF model id
- 依赖：`trl`、`transformers`、`datasets`（optional deps：`pip install axon-quant[sft]`）
